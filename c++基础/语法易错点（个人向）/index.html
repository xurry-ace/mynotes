    语法细节

    Quote

    “魔鬼藏在细节里，bug 也藏在细节里。”

    Tip

    下面是我刷题过程中遇到的一些语法细节我没注意，但是往往是这一个个细节决定你代码是否能跑得通，《道德经》有言“天下难事，必作于易；天下大事，必作于细。”，所以以下是我对于某些我不熟悉语法的归纳。平时按主题记录，涉及具体代码时则按代码中的出现顺序拆解。

    基础语法细节

    1. C++ 数组是否自动初始化为 0

    很多人误以为：

    int a[100];
long long dp[100];

    定义出来默认就是 0。这个理解不对。

    变量是否自动初始化，与 int、long long、数组类型无关，取决于变量定义的位置（存储期）。

    函数内部定义的局部变量：

    int main() {
    int a[10];
}

    数组元素默认是未定义值（垃圾值），直接使用可能导致结果错误。

    函数外定义的全局变量：

    int a[10];

    会自动初始化为 0。

    加 static 的变量：

    static int a[10];

    也会自动初始化为 0。

    很多初学者之所以误会，是因为某些编译器或调试环境碰巧把局部内存清零了，但这不是 C++ 语言保证，换平台后可能直接出错。

    竞赛中最常见问题是动态规划数组没初始化：

    long long dp[1005];
dp[i] += dp[i-1];

    此时 dp[i] 初始值是垃圾值，答案会错。

    正确写法：

    long long dp[1005] = {0};

    或：

    memset(dp, 0, sizeof(dp));

    记忆一句话：

    局部变量默认不安全，全局/static 默认是0，不确定就手动初始化。

    2. C++ 三目运算符（?:）与“比较写法”

    三目运算符是 C++ 中常用的简化判断表达式：

    a ? b : c

    含义是：如果 a 为真，取 b，否则取 c。

    常见用途（代替 if-else）

    int maxv = (x > y) ? x : y;

    等价于：

    if (x > y) maxv = x;
else maxv = y;

    易错点 1：嵌套三目可读性差

    int ans = a > b ? (a > c ? a : c) : (b > c ? b : c);

    虽然能用，但非常难读，建议改用 if。

    易错点 2：误把三目当“if语句”

    三目是表达式，不是语句，必须有返回值。

    ❌ 错误：

    a > b ? cout << a : cout << b;

    虽然能编译，但不推荐（副作用写法）。

    易错点 3：返回类型被“统一转换”

    三目运算符结果类型会自动统一：

    int x = (true ? 1 : 2.5);

    结果是 1.0 → 再转 int → 1（可能发生隐式转换）

    易错点 4：优先级坑

    int x = a + b > c ? 1 : 0;

    等价于：

    int x = ((a + b) > c) ? 1 : 0;

    但如果不加括号容易误读。

    常见应用场景

    • 取最大 / 最小
    • 简单条件赋值
    • inline 表达式简化

    三目运算符的嵌套 

    cout << ((mp[i][j] == 1) ? 1 : ((mp[i][j] == 3) ? 0 : 2)) << " ";
    详细见洛谷6_1求细胞数量最后我自己的做法

    一句话总结

    三目运算符是“表达式版 if-else”，能用就用简单情况，复杂逻辑一定换 if。

    3. 整数转化为字符串

    0~9可以通过
1. string s =char(1);
2. string s =1+'0';

    Danger

    但是这两种方法对于10以上的数字就会出问题，
    string s =1+'0';本质上是 ASCII 码值的计算，而ASCII 码值没有11，12...诸如此类

    错误代码 

    string s1 = i + '0';
    错误原因 1. int + char 运算后结果为 int（ASCII 数值运算）； 2. C++ 不支持 int 直接赋值给 string，类型不匹配编译报错； 3. i+'0' 仅适用于 0~9 单个数字，大数会乱码。

    正确写法

    to_string方法在头文件#include <string>中

    1. 任意数字转字符串（推荐） 
      string s1 = to_string(i);
    2. 单个数字 0~9 专用 
      char c = i + '0';
string s1 = c;
      核心口诀 数加字符变整数，整型不可赋字符串； 多位数字用to_string，单数字加零转字符。

    4. memset()函数的使用 C++ memset 知识卡片（简洁版）

    memset：按字节给一段内存批量赋值，常用于数组初始化。

    #include <cstring>
memset(数组名, 值, 字节数);

    常用写法

    int a[100];
memset(a, 0, sizeof(a));     // 全部置 0
memset(a, -1, sizeof(a));    // 全部置 -1
memset(a, 0x3f, sizeof(a));  // 设为大整数(常作 INF)

    为什么 memset(a,1,...) 不行？

    因为它按字节填充：

    01 01 01 01

    一个 int 会变成：

    16843009

    不是 1。

    适用场景

    int a[1000];
bool vis[1000];
char s[1000];
int mp[100][100];

    数组清零、标记数组、二维数组初始化都很常用。

    不适用场景

    vector<int>
string
set / map
类对象

    这些是对象类型，不要用 memset。

    Note

    更安全的替代写法

    fill(a, a+n, 1);

    给数组赋非 0 / -1 值时，优先用 fill()。

    一句话记忆

    memset 是按字节赋值。

    所以：

    0     最安全
-1    常用
0x3f  常作 INF
1~100 别乱给 int 数组用

    一组竞赛代码中的语法拆解

    下面这组语法来自同一版代码，我按它们在代码中的出现顺序拆开记录。

    1. 加速读入

    ios::sync_with_stdio(false);
cin.tie(nullptr);

    竞赛中经常把这两行放在 main 开头，用来减少输入输出的额外开销。

    • sync_with_stdio(false)：关闭 C++ 的 cin/cout 与 C 的 scanf/printf 之间的同步。关闭后，标准 I/O 流可以使用自己的缓冲策略，大量读入时通常更快。关闭同步后不要再混用这两套输入输出，否则输出顺序等行为可能不符合预期。
    • cin.tie(nullptr)：cin 默认与 cout 绑定，每次从 cin 读入前都会先刷新 cout 的缓冲区。解绑后省去这次刷新，在大量输入时尤其有用。

    这两行不是任何程序都必须写的模板；需要频繁读写、且确定不混用 C/C++ 两套 I/O 时，它们才有明显价值。

    2. Lambda 表达式

    auto win = [](int a, int b, int target){
    return (a >= target || b >= target) && abs(a - b) >= 2;
};

    基本结构是：

    [捕获列表](参数列表) -> 返回类型 { 函数体 }

    其中返回类型常常可以省略，让编译器根据 return 自动推导。

    • [] 是空捕获列表：这个 lambda 不使用外部的局部变量，只使用自己的参数。若要使用外部变量，可以写 [&]，表示按引用捕获函数体中用到的可捕获局部变量；也可以写 [x, &y]，分别指定按值捕获 x、按引用捕获 y。
    • (int a, int b, int target) 是参数列表，写法与普通函数一致。
    • 这里的 return 返回 bool，所以返回类型可以自动推导。显式指定时，可以写成 [](int a) -> bool { return a > 0; }。
    • auto 让编译器推导变量 win 的类型。之后可以像调用普通函数一样写 win(x, y, 11)。

    可以把它理解为一个写在局部的小函数；严格来说，win 保存的是一个可调用对象。这里不需要捕获外部变量，所以空捕获最清楚，也避免了不必要的依赖。

    3. cin >> c 的两个关键性质

    while (cin >> c && c != 'E') {
    // 处理字符 c
}

    第一，格式化字符输入默认跳过空白字符。 空格、换行和制表符都会被跳过，读到的是其他实际字符。因此，即使输入分散在多行，这段代码也不需要自行处理换行。

    第二，提取表达式可以参与条件判断。 cin >> c 返回输入流本身的引用；在条件语境中，流会检查当前状态。读取成功时可以继续执行，读取失败或读到文件末尾而无法完成提取时，条件为假。

    && 还有短路求值：只有 cin >> c 成功时，才会继续判断 c != 'E'。所以这个循环同时处理两种结束情况：

    1. 无法继续读入字符；
    2. 成功读到结束标记 'E'。

    4. string 的拼接

    s11 += to_string(x) + ":" + to_string(y) + "\n";
    • to_string(x) 把整数 x 转成 string，声明在头文件 <string> 中。这也是前文“整数转化为字符串”的一次实际应用。
    • + 用于拼接字符串，并从左向右计算。to_string(x) + ":" 先得到一个 string，再继续拼接后面的内容。
    • 字符串字面量不能直接与另一个字符串字面量相加，例如 "a" + "b" 是非法的。字面量的类型是字符数组，在这个表达式中会退化为指针，不能按 string 的方式相加。参与某一次 + 运算的操作数中至少有一个是 string，才能使用字符串拼接。
    • += 把右侧内容追加到 s11 末尾。string 会自行管理存储空间，因此不需要像固定长度的 char a1[100000] 那样自己控制容量和下标。

    "\n" 是字符串字面量，'\n' 是字符。这里两种写法都能完成拼接，但追加一个换行符时，写成 s11 += '\n'; 更直接；本例因为要连续拼接，使用 "\n" 也很自然。

    5. 逗号运算符

    if (c == 'W') x++, m++;

    x++, m++ 是一个逗号表达式：先执行 x++，再执行 m++，整个表达式的值是最后一个子表达式的值；这里不使用这个结果，只利用两次自增的副作用。

    if 后面本来就需要一条语句，而 x++, m++; 恰好是一条表达式语句，所以不写花括号也能同时修改两个变量。

    不过，这种写法容易让读者误以为只有 x++ 属于 if。更清楚的写法仍然是：

    if (c == 'W') {
    x++;
    m++;
}

    逗号运算符在 for 循环中更常见，例如：

    for (int i = 0, j = n - 1; i < j; i++, j--) {
    // 同时从两端向中间移动
}

    6. abs 的头文件

    #include <cstdlib>

int d = std::abs(a - b);

    处理 int 的 std::abs 由 <cstdlib> 提供；浮点数版本由 <cmath> 提供，<algorithm> 并不提供 abs。

    有些编译环境会通过其他头文件间接引入相关声明，所以漏写 <cstdlib> 也可能碰巧编译通过。但间接包含不是可以依赖的接口，使用哪个标准库功能，就应包含它对应的头文件。前文“cmath 常用函数”还对比了 abs 与 fabs。

    7. if-else if 链与 continue

    if (c == 'W') x++, m++;
else if (c == 'L') y++, n++;
else continue;

    这几个分支按顺序判断，并且只会执行其中一个：

    • c == 'W'：执行第一组加分操作；
    • 否则，若 c == 'L'：执行第二组加分操作；
    • 其他字符：执行 continue，跳过本轮循环剩下的赢局判断，直接回到 while 的下一轮条件判断。

    虽然 cin >> c 已经跳过空白字符，但遇到除 'W'、'L' 之外的其他字符时，else continue 仍能明确地把它们忽略。结束标记 'E' 不会进入这里，因为循环条件已经先终止了循环。

    8. 全局数组与局部数组的初始化

    int a1[100000], b1[100000];  // 定义在 main 外面

    这一条与前文“数组是否自动初始化为 0”相呼应。

    全局数组具有静态存储期，如果没有显式初始化，元素会被零初始化，因此上面两个数组最初全部为 0。main 内未初始化的普通局部数组则不同，其元素值是不确定的，不能把它理解为一批可靠的“随机数”；读取未初始化的元素会产生错误，程序行为也无法依赖。

    如果确实需要局部数组清零，应明确写出：

    int a1[100000] = {0};

    这会把所有元素初始化为 0，而不只是第一个元素。改用 string 累积结果后，不再依赖这两个数组保存输出，也就不用担心它们的初始值了。

    结构体、函数与输入输出中的语法坑

    这一组按错误类型整理。vector、string 和数学函数的基本用法已有专页，这里只记录我实际踩过的错误及原因，不重复整份函数清单。

    1. struct 定义：不要括号，末尾加分号

    // 错误：struct 不是函数，类型名后不能写 ()
struct Student() { int a; };

// 正确：定义类型
struct Student { int a; };

// 正确：定义类型的同时定义变量 s
struct Student { int a; } s;

    struct Student { int a; } s; 是“定义类型并定义变量”，不是 C++11 的初始化列表。若已经定义好 Student，C++11 起可以用聚合初始化：

    Student s{10};

    结构体定义右花括号后的分号也不能漏：

    struct S { int x; };  // 末尾必须有分号

    2. 函数参数：只读对象常用 const &

    // 可能导致类型不匹配：非 const 引用不能绑定 const 对象
bool cmp(string& a, string& b);

// 比较函数只读取对象，不修改对象
bool cmp(const string& a, const string& b);

    const string& 同时表达两件事：按引用传递，避免复制字符串；承诺函数不修改参数。sort 的比较函数不应修改参与比较的元素，因此通常采用这种写法。

    这不是说所有参数都必须使用 const &。int 等小型基本类型直接传值通常更简洁；需要修改外部对象时，则应使用非 const 引用。

    3. 传值、传引用与返回新值

    // A：传值，修改的是副本，调用者看不到变化
void addX(string s) {
    s += "x";
}

// B：传引用，修改的就是调用者提供的对象
void addXRef(string& s) {
    s += "x";
}

// C：在副本上生成并返回新值，原对象不变
string withX(string s) {
    s += "x";
    return s;
}

    第三种写法需要接住返回值，例如 v.push_back(withX(x));。如果只是调用 withX(x); 却丢弃返回值，外部同样得不到新结果。

    口诀：想让外面变，要么用 & 修改原对象，要么 return 新结果并接住它。

    4. vector 尾插：push_back，不是 push

    vector<string> v;
v.push("a");       // 错误：vector 没有 push 成员
v.push_back("a");  // 正确

    push 常见于 stack、queue 等容器适配器；vector 的尾部插入叫 push_back。其他 vector 操作见 vector 常用用法。

    5. cin >> string：按“单词”读取

    string x;
while (cin >> x && x != ' ') { }  // 错误：string 不能直接与 char 比较
while (cin >> x) { }              // 可以：读取失败或文件结束时退出

    前文 cin >> c 已经说明了“跳过空白”和“流可作为循环条件”。对 string 还要补充一点：格式化提取会先跳过前导空白，再持续读入，直到下一个空白前停止。因此 x 读入的是一段不含空白的字符序列，不可能只读到空格或换行。

    这里的分隔空白仍留在输入流中，这正是后面混用 getline 时需要注意的地方。

    6. string 和 char 不能混着比较

    string s = "a";

if (s == 'a')    // 错误：没有 string == char 的比较运算符
if (s == "a")    // 正确：string 可以与字符串字面量比较
if (s[0] == 'a') // 正确：s[0] 是 char

    双引号表示字符串字面量，单引号表示字符。比较整个字符串用 "a"，比较字符串中的一个字符用 s[0] == 'a'；使用下标前还要确保该位置确实存在。

    7. 成员访问：. 后面直接跟成员名

    a.score.[i]  // 错误：. 后不能直接接 []
a.score[i]   // 正确：先取成员 score，再取第 i 个字符
a[i]         // 若 a 是没有 operator[] 的结构体，则错误

    可以把 a.score[i] 的求值顺序理解为 (a.score)[i]。第一步通过 . 访问结构体成员，第二步通过 [] 访问这个 string 成员中的字符，不需要在 . 和 [] 之间再加点。

    8. sort 比较函数：所有路径都要返回，等价时返回 false

    bool cmp(const S& a, const S& b) {
    if (a.x != b.x) return a.x > b.x;
    if (a.y != b.y) return a.y > b.y;
    return false;
}

    返回类型写成 bool，并不代表编译器能保证每条路径都有返回值。若所有关键字都相等时漏掉最后的 return，控制流到达函数末尾而没有返回值，会产生未定义行为。

    sort 要求比较函数表示严格弱序。在这道题的多关键字比较中，可以抓住两个直观要求：不能让 cmp(a, a) 为真；若两个元素在所有排序关键字上等价，则 cmp(a, b) 和 cmp(b, a) 都应为 false。因此不能简单地把最后的兜底写成 true，也不要用 >= 代替 > 来表示“先于”。

    9. string 自带字典序比较

    return a > b;

    string 已重载 <、>、== 等比较运算符，通常不需要手写逐字符循环。比较会按字符值依次进行；常见 OJ 的字母、数字场景中，可以理解为按 ASCII 值比较。

    直接比较还会正确处理长度和前缀。例如 "ab" < "abc" 为真，因为前两个字符相同，而前者先结束。手写循环若只遍历到某个字符串的长度，却忘记处理“一个是另一个的前缀”的情况，反而容易出错。

    10. 类型转换：人数和次数不要用 double

    double n, m;
cin >> n >> m;
vector<S> v(n);          // double 隐式转换为 size_type，可能截断
for (int i = 0; i < n; i++) { }  // 循环中发生 int 与 double 的比较

    n 表示元素个数时，应使用整数类型：

    int n, m;
cin >> n >> m;
vector<S> v(n);

    隐式转换“能编译”不代表类型选择合理。人数、次数、下标和容器长度本来都是整数，直接用 int 或合适的无符号类型，可以避免截断及负数、过大值带来的问题。

    11. 循环变量与 size() 的类型

    for (int i = 0; i < a.size(); i++) { }

    a.size() 返回容器的 size_type，通常是 size_t，属于无符号整数类型。与 int 比较时会发生有符号、无符号转换，编译器可能给出警告；当 i 为负数时，问题尤其危险。

    容器长度确定不会超过 INT_MAX 时，可以使用显式转换：

    for (int i = 0; i < static_cast<int>(a.size()); i++) { }

    更通用的下标写法是：

    for (size_t i = 0; i < a.size(); i++) { }

    如果不需要下标，范围 for 更简洁：

    for (const auto& x : a) {
    // 只读遍历元素
}

    auto i = 0u 只能推导出 unsigned int，不保证与容器的 size_type 完全一致，因此这里不把它作为首选。

    12. getline 与 cin >> 混用：处理残留换行

    int n;
cin >> n;             // 读完数字，后面的换行仍留在输入流中

string s;
getline(cin, s);      // 立即读到这个换行，因此得到空字符串

    若数字后只需要丢弃一个换行符，可以写：

    cin >> n;
cin.ignore();
getline(cin, s);

    若还要丢弃该行剩余的其他字符，更稳妥的写法是：

    #include <limits>

cin >> n;
cin.ignore(numeric_limits<streamsize>::max(), '\n');
getline(cin, s);

    这里的“清缓冲区”更准确地说，是丢弃当前行尚未读取的字符，直到并包括换行符。如果本来就想保留整行输入中的前导空格，则不要提前用 cin >> 读取该行。

    13. 循环控制变量被覆盖：语法合法，逻辑出错

    int n;
cin >> n;  // n 是总人数

for (int i = 0; i < n; i++) {
    cin >> n >> m >> t;  // 错误：读入数据时把总人数 n 覆盖了
}

    循环每轮都会用新的 n 判断 i < n，因此循环次数可能被意外改变。这个错误不是变量遮蔽，因为这里使用的是同一个 n，而不是在内层重新定义变量。

    原则：循环上界和本轮读入的数据分开命名。 例如保留 n 表示总人数，用 score、time 等名称保存每个人的数据。

    14. return 后别忘分号

    return (a.score > b.score)   // 错误：缺少分号
return (a.score > b.score);  // 正确

    括号只包围表达式，不能代替语句末尾的分号。return、变量定义和表达式语句通常都需要以 ; 结束。

    15. floor 等取整函数的头文件

    #include <cmath>

double result = floor(m * 1.5);

    floor 是向下取整，不是取模，声明在 <cmath> 中。它与 ceil、round 等函数的区别已整理在 cmath 常用函数，这里不再重复。

    这些语法点适合作为写完代码后的检查清单；它们能减少编译错误，但不能代替对算法逻辑和边界条件的检查。

    写代码前的纯语法速查卡

    这张表只保留最容易写错的七条，方便写代码前快速扫一遍；完整解释仍以上文对应主题为准。

    语法点 你写的 正确写法 为什么
    1. 局部计数数组先清零 int data[26]; int data[26] = {0}; 未初始化的普通局部数组，其元素值不确定。后面若直接 data[i]++，必须先把计数起点设为 0。
    2. 数组不能整体赋值 data_sort[] = data[]; memcpy(data_sort, data, sizeof data_sort);（需 <cstring>） 内置数组不能整体赋值，数组名也不能通过 = 改指向另一个数组。对于这里的 int 数组，可以复制字节或逐元素赋值；vector<int> b = a; 则属于容器的复制规则。
    3. 原生数组没有 .begin() 成员 sort(data_sort.begin(), data_sort.end()); sort(data_sort, data_sort + 26); 原生数组没有容器那样的成员函数。sort 可以接收首元素指针和尾后指针；降序时再加 greater<int>()。
    4. 声明与元素更新别混写 int data_sort[p[i]-'A'] += 1; data_sort[p[i]-'A']++; 类型名用于定义变量，下标表达式用于访问已有元素，+= 不能这样充当数组定义的初始化器。数组先在外层定义，这里只更新一个元素。
    5. char 与下标互换 data[p[i] - 'A']++; int j = p[i] - 'A';
    char c = char('A' + j);    		 在常见 ASCII/OJ 环境中，大写字母连续编号：减 'A' 得到 0～25 的下标，加 'A' 再转回对应字母。输入必须满足题目约定的字符范围。
    6. size() 的无符号类型 for (long unsigned int i = 0; i < p.size(); i++) for (size_t i = 0; i < p.size(); i++) size_t 更直接地表达长度和下标的含义。若题目保证每行不超过 100 个字符，也可用 i < static_cast<int>(p.size())；不能把这个强转无条件用于超大容器。
    7. 按行读与按内容读 cin >> p;（却想保留整行及空格） getline(cin, p);
    cin >> ch;    		 在乎“第几行”和行内空格时用 getline；只在乎一个个非空白字符时用 cin >> ch，它默认跳过空格、换行和制表符。

    写循环前的四项默检

    • 需要清零的局部计数数组写 = {0} 了吗？
    • 原生数组被误当成 vector，使用整体赋值或 .begin() 了吗？
    • 把变量定义和已有元素的更新混在同一条声明里了吗？
    • 每个变量使用前都有初值吗，尤其是 max_tmpt 这类保存最值的变量？
