# 缓冲与磁盘

!!! note "本页内容边界"
    目前先补机械磁盘调度的固定请求模型。缓冲技术、设备分配和带时间参数的综合题仍待整理；本页计算不对应你的王道教材题号。

## 已经知道数据在哪，为什么还需要调度？

多个磁盘请求都在等待时，处理顺序会改变磁头需要移动的距离。**寻道**是磁头移动到目标磁道的过程；实际访问还涉及旋转延迟与传输等开销。下面只把磁道号当作一维位置，研究请求顺序，不把移动距离直接当作响应时间。

机械磁盘的定位成本与调度背景参考 [OSTEP：Hard Disk Drives](https://pages.cs.wisc.edu/~remzi/OSTEP/file-disks.pdf)。SSD 没有这样的机械磁头，不能直接套用本页位置尺。

## 对照 FCFS、SSTF、SCAN 与 LOOK { #disk-lab }

| 算法 | 下一步依据 |
| --- | --- |
| FCFS | 按请求输入顺序服务 |
| SSTF | 选距当前磁头最近的请求 |
| SCAN | 沿当前方向服务；为处理另一侧请求，先到磁盘端点再折返 |
| LOOK | 沿当前方向服务；到该方向最后一个请求处就可折返 |

<div class="study-viz concept-lab" data-concept-viz="disk">
<p>静态算例：磁道 0～199，初始磁头 53，请求为 98,183,37,122,14,124,65,67。初始向大磁道时，SCAN 先服务 65,67,98,122,124,183，再经过端点 199，最后服务 37,14，总移动 331 个磁道；LOOK 在 183 折返，总移动 299。FCFS 为 640，SSTF 为 236。</p>
</div>

!!! info "演示规则：先说清端点与停止条件"
    全部请求在开始时已经到达，不再加入新请求。完成全部请求后立即停止，不额外扫到另一端。SCAN 在仍有另一侧请求时才继续到端点折返，这段移动计入总量；LOOK 在本方向最后一个请求处折返。起点请求立即服务；重复磁道保留为不同请求；SSTF 等距时选较小磁道，同磁道按输入顺序。方向选项只影响 SCAN 和 LOOK。

每一步显示磁头的上一个位置、当前位置，以及该步移动。**端点 199 不是输入中的请求**，所以默认 SCAN 比 LOOK 多一次移动动作，但不会多完成一个请求。

## 同一服务顺序，为什么移动距离不同？

默认 SCAN 与 LOOK 的请求服务顺序相同：

```text
65 → 67 → 98 → 122 → 124 → 183 → 37 → 14
```

但 SCAN 在 183 与 37 之间还要经过 199。用总路程独立核对：

- SCAN：从 53 向上到 199，再向下到 14，`(199-53)+(199-14)=331`。
- LOOK：从 53 向上到 183，再向下到 14，`(183-53)+(183-14)=299`。
- 差值为 `32`，正是额外的 `183→199→183` 这段往返。

算法差别及传统示例可参考 [UIC：Mass-Storage Structure](https://www.cs.uic.edu/~jbell/CourseNotes/OperatingSystems/10_MassStorage.html)。计算题若使用不同的初始方向、端点或统计停止条件，应按题设重画路径。

## 最近优先，就一定全局最短吗？

SSTF 每一步只做局部最近选择。默认序列中其总移动是 236；如果先处理较小侧的 37、14，再一路处理较大侧到 183，总移动是 `(53-14)+(183-14)=208`。这已经足以说明 SSTF 不保证全局最短。

若持续有新请求到来，远处请求还可能长期等待；本页有限、静态的序列本身不能用来测量这种饥饿情况。要分析公平性，还要明确到达过程与调度规则。

### 自测：两次请求同一磁道，要移动两次吗？

切换到“起点请求、等距与重复”，选 SSTF，并保持初始磁头为 53。序列 `53,43,63,43` 会怎样处理？

??? success "展开核对"
    先服务起点 53，不移动；43 与 63 等距，按本页约定选 43；另一个 43 是独立请求，但无需再移动；最后到 63。服务了 4 个请求，总移动 `0+10+0+20=30` 个磁道。不能在计算前直接把重复请求删掉。
